PART 2 -- WHAT WAS ACTUALLY WRONG AND FIXED (this session's last two rounds)
================================================================================
For the full history of everything found and fixed across the WHOLE session,
see FINAL_DeepScan_Report_2026-09-11.txt and the other dated report files in
this folder. The two things worth knowing by name, because they were the most
serious:

1. ESP1 -- a genuine cross-core race condition (HIGH severity). The new
   "hold-to-run" feature's Firebase-polling function was calling functions
   that mutate core-1-owned state (a global String log buffer, the ESP2 UART)
   directly from core 0. Two FreeRTOS tasks on two physical cores touching the
   same unlocked String is a real heap-corruption risk -- the exact bug class
   this file had already been fixed for, twice, elsewhere. Found by an
   independent fresh audit, verified by hand (traced which core every related
   function actually runs on), and fixed by splitting the function into a
   pure core-0 data hand-off with all the actual logic moved to code that
   already runs safely on core 1.
   A second bug was self-caught while implementing that fix, before it ever
   reached a build: the hand-off buffer was sized for 8 bytes, but the longest
   valid input ("transfer") needs 9 -- would have silently broken that one
   button's requests via a truncated string comparison.

2. Website/Firebase -- a rule/client mismatch (medium severity). The
   hold-to-run feature's release write (letting go of a held button) required
   the same privileged-tier check as acquiring it, when it should have been
   let through unconditionally like the equivalent /irrigation/manual rule
   already does -- an operator withdrawing someone's access mid-press could
   have gotten a server-side permission error on release instead of a clean
   stop. (Physical safety was never actually at risk here either way -- ESP2's
   own 400ms hardware dead-man and ESP1's own timeout are both completely
   independent of this Firebase flag.)

Plus 3 more low-severity items (a client-side privilege check one layer deeper
than it needed to be, a DOM-node cleanup edge case in the new toast
notifications, and an error-handling nuance in the account-delete function) --
all fixed, all detailed in FINAL_DeepScan_Report_2026-09-11.txt.
