3. CONFIRMATION THAT NO OTHER FUNCTIONAL CHANGES WERE MADE
--------------------------------------------------------------
Pre-edit inspection found the following additional references, none of which needed or received any
change:
  - ESP1: `strlcpy(c.colMode, req["payload"]["mode"] | "", sizeof(c.colMode));` (:6086) uses
    `sizeof(c.colMode)`, which auto-adjusts to the new size -- untouched, no hardcoded "14" anywhere.
    The two `strcmp(c.colMode, "AUTO"/"IRRIGATION_ONLY")` validation checks (:6375-6376) are
    content-based comparisons, unaffected by buffer size, and were left exactly as-is. A
    similarly-named but unrelated function, `colMode3()` (LCD 3-state column-mode editor,
    :8346/8458/8636), operates on a completely different variable (`col[c].mode`) and was not
    touched.
  - ESP2: `INVERTER_WARMUP_MS` has exactly one usage site (`stagePoll()`, :1044). The sibling
    constant `VALVE_SWITCH_MS = 1000` (the DC-stage settle time, :165) is a separate constant and
    was NOT changed. Verified that `sgT0` (the timer this constant is measured against) is reset to
    `millis()` at the moment the pump actually energizes (inside `stagePoll()`, right after
    `pcfOn(sgPump)`), so `FLOW_TIMEOUT_MS` (the no-flow fault timeout) and the per-stage hard cap are
    both measured from pump-ON, not from stage-begin -- this change only delays WHEN the pump turns
    on; it does not shorten or otherwise touch the flow-fail detection window, the stage time cap, or
    any other safety timeout.
  - Confirmed the pump sequence itself was not touched: `SEQ_FILL`/`SEQ_DELIVER` still transition
    through the same `goStep()` calls, the transfer pump is still turned off (`stageEnd()` inside
    `endMeteredStage()`) before the state machine advances to the deliver stage, and `FLOW_FAIL`/
    `PWR_FAIL`/`PZEM_V_MIN`/`PZEM_V_MAX`/`PZEM_OVERCURRENT_A`/`PZEM_MIN_CURRENT_A` and the emergency-
    stop path (`MODE+BACK` -> `enterEmergencyStop`) are all untouched -- none of these symbols appear
    anywhere near either edited line, and neither edit is a `#define`/`#if` that could compile out
    any safety code.
  - No repository (git) is present at this project root, so no `git diff` was available as a second
    proof; instead, scope was verified directly via the Edit tool, which requires an exact, unique
    match against the existing text -- providing tool-level certainty that only these two single
    lines were changed in each file.
