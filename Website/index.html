Three physical zone profiles

A, B, and C remain the physical ESP1 zone identifiers. Crop profiles are dashboard planning notes only: the current ESP1 firmware does not read them to start or change an irrigation run.

Safe remote controls

ESP1 validates every request before it reaches ESP2, and refuses anything that arrives while the system is not safely idle. A “queued” badge is not confirmation that anything moved — wait for ESP1’s own status.

System control

Available at any time, not just during a fault. Disabling actuations keeps every sensor, log and upload running but blocks scheduled runs, pump exercises and forced runs — and it survives a reboot, so a power blip cannot quietly re-arm the pumps. Re-enable from here or from the LCD (Settings > Enable Actuations, which appears only while disabled).

Emergency system stop

Immediately queues an ESP1 emergency-stop request. It is never blocked by the normal 10-second cooldown or by stale live telemetry. “Queued” is not physical-stop confirmation; wait for ESP1’s command status. Use Return to normal in the banner above to come back out.

Forced irrigation / fertigation

Sends a real FORCE_RUN work order. This overrides the schedule, the soil-moisture threshold and serviced-today — it does not override hardware safety, and ESP1 still refuses it unless the system is idle and the reservoir is above its low mark. Leave every nutrient at 0 for plain irrigation; any non-zero dose makes it a fertigation.

Nutrients (mL) — leave at 0 for irrigation

Limits mirror the firmware: at most 20 L total per request and 500 mL per nutrient. Mixing time and run duration are not settable — ESP1 mixes for its compiled duration and runs to the metered volume, not to a clock. ESP1 re-checks safety when the countdown expires, so a fault or a falling reservoir during the delay cancels the run instead of starting it late.

Distribution valves / solenoids

There are deliberately no Valve A/B/C buttons. ESP1 rejects a standalone remote solenoid request as “not a remotely safe control”, and there is no relay feedback to confirm what a valve actually did, so such a button would report success it cannot verify. Valves are opened only as part of a work order, where ESP2 sequences and closes them.

Direct hardware control

This tab drives the hardware directly

Every control here energises a relay immediately — pumps, valves and the mixer — with none of the checks a scheduled run goes through. The pH pumps dispense corrosive adjuster into the mixing tank, and the nutrient pumps dispense concentrate. Nothing here waits, and nothing here asks a second time.

ESP1 still refuses anything that arrives while the system is not idle, and ESP2 stops any pulse on its own if this page or ESP1 goes quiet. Those are backstops, not permission.

Manual actuator tests

Each test runs for a set number of seconds and stops on its own. Where the output has a flow meter, the result reports how many pulses it saw — that is how you tell a working pump from a dead pump, a blocked line or a dead sensor, without walking to the rig.

Preventive pump exercise

ESP1 runs each pump briefly every 2 days so it cannot seize between irrigations. Turning it off stops that entirely — useful on a battery rig, or when the mixer would otherwise spin in an empty tank.

Timed pulses

Drives the same relay combinations the LCD Testing screen offers, but on a timer rather than a held button. Transfer runs as the fill combination (reservoir valve + pump), because running that pump against a shut valve dead-heads it.

ESP2 sensors

ESP2 is powered down between runs, so its sensors are not streamed continuously. Running a sweep powers it up, reads pH / EC / current / PZEM / flow counters, then powers it back off. Idle-only.
