Three physical zone profiles

A, B, and C remain the physical ESP1 zone identifiers. Crop profiles are dashboard planning notes only: the current ESP1 firmware does not read them to start or change an irrigation run.

Safe remote controls

ESP1 validates every request before it reaches ESP2, and refuses anything that arrives while the system is not safely idle. A “queued” badge is not confirmation that anything moved — wait for ESP1’s own status.

Transfer pump test

ESP1 safe exercise: 5 seconds.

Booster pump test

ESP1 safe exercise: 5 seconds. The exercise has no destination — ESP1 runs the pump only, and does not open a distribution valve.

Tank mixer test

ESP1 safe exercise: 5 seconds. This dashboard does not change inverter settings.

Emergency system stop

Immediately queues an ESP1 emergency-stop request. It is never blocked by the normal 10-second cooldown or by stale live telemetry. “Queued” is not physical-stop confirmation; wait for ESP1’s command status.

Forced irrigation / fertigation

Sends a real FORCE_RUN work order. This overrides the schedule, the soil-moisture threshold and serviced-today — it does not override hardware safety, and ESP1 still refuses it unless the system is idle and the reservoir is above its low mark. Leave every nutrient at 0 for plain irrigation; any non-zero dose makes it a fertigation.

Nutrients (mL) — leave at 0 for irrigation

Limits mirror the firmware: at most 20 L total per request and 500 mL per nutrient. Mixing time and run duration are not settable — ESP1 mixes for its compiled duration and runs to the metered volume, not to a clock.

Distribution valves / solenoids

There are deliberately no Valve A/B/C buttons. ESP1 rejects a standalone remote solenoid request as “not a remotely safe control”, and there is no relay feedback to confirm what a valve actually did, so such a button would report success it cannot verify. Valves are opened only as part of a work order, where ESP2 sequences and closes them.

ESP1 diagnostics

Actual diagnostics published by ESP1. Credentials, tokens, keys, and private service values are never displayed — only whether a service is configured.
